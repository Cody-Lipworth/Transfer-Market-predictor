# Transfer Value Predictor

Predicts a football player's transfer market value (EUR) from a player-season
of performance stats, using a linear regression model (with Ridge and
ElasticNet variants for comparison) trained on the Kaggle "Football Data from
Transfermarkt" dataset. Includes a FastAPI backend and a static frontend
(a Claude Design canvas) for browsing players and running predictions.

## Quick start

Once you've fetched the data and trained a model at least once (see below),
start both the backend and frontend with one command:

```bash
./run.sh
```

It waits until both are actually ready, then prints the URL to open. Ctrl+C
stops both cleanly.

## Project structure

```
transfer-value-predictor/
├── run.sh              # starts backend + frontend together
├── api/                # FastAPI app (app.py) + JSON Schema contract
├── src/                # data pipeline: fetch_data, wrangle, train_model, evaluate, predict
├── frontend/            # static frontend (Claude Design canvas), no build step
├── data/                # raw/processed CSVs (gitignored, regenerated by the pipeline)
├── models/              # trained model .pkl (gitignored, regenerated by train_model)
├── outputs/figures/      # evaluation plots (gitignored, regenerated by evaluate)
└── notebooks/            # optional EDA notebook
```

## First-time setup

### 1. Get a Kaggle API token

1. Create a free account at https://www.kaggle.com
2. Go to **Account settings > API > Create New Token** — this downloads `kaggle.json`
3. Place it at `~/.kaggle/kaggle.json` and restrict its permissions:
   ```bash
   mkdir -p ~/.kaggle
   mv ~/Downloads/kaggle.json ~/.kaggle/kaggle.json
   chmod 600 ~/.kaggle/kaggle.json
   ```

If you'd rather not use the API, download the dataset manually from
https://www.kaggle.com/datasets/davidcariboo/player-scores and unzip the CSVs
(`players.csv`, `player_valuations.csv`, `appearances.csv`, `games.csv`,
`clubs.csv`, `competitions.csv`) into `data/raw/`.

### 2. Install dependencies

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

### 3. Run the pipeline end-to-end

```bash
python -m src.fetch_data          # download + cache raw CSVs into data/raw/
python -m src.wrangle             # clean, merge, engineer features -> data/processed/dataset.csv
python -m src.train_model         # fit pipeline -> models/linear_regression_model.pkl
python -m src.evaluate            # metrics + plots -> outputs/figures/
```

Use `--model ridge` or `--model elasticnet` on `train_model` / `evaluate` to
compare regularized variants against plain linear regression.

Predict a single player from the command line:

```bash
python -m src.predict --goals 18 --assists 9 --age 24 --minutes-played 2700 --position FWD
```

After this, `./run.sh` (see Quick Start above) will work.

## Frontend

`frontend/transfer-value-predictor.dc.html` is a static, single-file
frontend (a Claude Design canvas component) with a Player Directory,
Player Detail page, and a Predict form. It has no build step and no
dependencies beyond `frontend/support.js` (its runtime, loads React from a
CDN) — `run.sh` serves the folder as-is with Python's `http.server`.

It talks directly to the FastAPI backend via `fetch()`, with the base URL
set once at the top of the `<script data-dc-script>` block
(`API_BASE_URL`) — change that one constant to point it at a different
backend.

## Run the API on its own

```bash
uvicorn api.app:app --reload
```

Endpoints:

- `GET /players` — the full processed dataset (for a table view)
- `GET /players/{name}` — one player's latest-season stats + predicted value
- `POST /predict` — accepts stats JSON, returns a predicted value
- `POST /refresh` — re-downloads the dataset, re-wrangles, and retrains the
  model in the background (what an "Update data" button should call). Returns
  `202 {"status": "running"}` immediately, or `409` if a refresh is already
  in progress. Takes roughly 1-3 minutes end-to-end (mostly the Kaggle
  download), so the frontend should poll status rather than wait on this call.
- `GET /refresh/status` — poll after `POST /refresh`:
  `{"status": "idle" | "running" | "done" | "error", "started_at": ..., "finished_at": ..., "error": ...}`

### Example: `POST /predict`

```bash
curl -X POST http://127.0.0.1:8000/predict \
  -H "Content-Type: application/json" \
  -d '{
        "goals": 18,
        "assists": 9,
        "age": 24,
        "minutes_played": 2700,
        "position_group": "FWD",
        "minutes_share": 0.85
      }'
```

```json
{
  "predicted_value_eur": 30238845.54997065
}
```

CORS is wide open (`allow_origins=["*"]`) so a separately hosted frontend
(e.g. a Claude Design app) can call this API directly during development.

## Features

| Feature | Description |
|---|---|
| `goals`, `assists` | Season totals |
| `goals_per_90`, `assists_per_90` | Rate stats, scaled to 90 minutes |
| `age` | Age at the end of the season |
| `years_from_peak` | `abs(age - 27)` |
| `minutes_played` | Season total minutes |
| `minutes_share` | `minutes_played / max minutes played that season` (availability proxy) |
| `position_group` | One-hot encoded `GK` / `DEF` / `MID` / `FWD` |

`image_url` (a Transfermarkt player portrait) is also carried through into
`data/processed/dataset.csv` and the API as display metadata — it is not
used as a model feature.

Player-seasons under 450 minutes are excluded to keep per-90 rates meaningful.

## Results

Trained on the real Kaggle dataset (69,201 player-seasons, players with
≥450 minutes played in a season):

| Model | R² | MAE | RMSE |
|---|---|---|---|
| Linear Regression | 0.299 | €5.27M | €9.55M |
| Ridge (α=10) | 0.299 | €5.27M | €9.55M |
| ElasticNet (α=0.1, l1_ratio=0.5) | 0.295 | €5.25M | €9.57M |

Regularization barely changes the fit — with 69K rows the correlated
features (`goals`/`goals_per_90`, `minutes_played`/`minutes_share`) aren't
causing much overfitting, so plain linear regression performs about as well
as its regularized variants and is the simplest choice to ship.

**Features that matter most** (by standardized coefficient magnitude, see
`outputs/figures/coefficients.png`): `goals`, `assists`, and `minutes_share`
push predicted value up the most; `age` and playing as a forward (`FWD`)
push it down; goalkeepers (`GK`) skew up relative to the position baseline.

`outputs/figures/predicted_vs_actual.png` shows the model's main weakness in
practice: it systematically **underpredicts superstar-tier players**
(>€50M actual value) — exactly the non-linear "hype premium" a linear model
can't capture, see limitations below.

## Model limitations

- **Small, noisy label**: market valuations are analyst estimates updated
  periodically, not transaction prices — they lag real form and can be sticky.
- **Non-linear value dynamics**: transfer value doesn't scale linearly with
  output (a young player with modest stats can be worth more than an older
  player with better ones); linear/Ridge/ElasticNet can't capture that curvature.
- **Missing context**: injury history, contract length/expiry, agent/club
  negotiating leverage, league prestige, and reputation/hype all move real
  valuations but aren't in this feature set.
- **Static snapshot**: the Kaggle dataset is a point-in-time export, so
  predictions reflect the data as of whenever it was downloaded, not live
  transfer activity.
